# Obsidian SEO Audit Implementation Plan

**Goal:** Implement the supplied technical specification as a standalone Obsidian plugin, without commits.

**Architecture:** Sample Plugin build layout; framework-free ItemView; isolated parser, index, transport, scan queue, persistence and export modules. Versioned settings and latest-result cache use separate keys in Obsidian plugin data; URL records allow later history extensions.

**Tech stack:** TypeScript, Obsidian API, esbuild, Vitest + jsdom.

**Spec:** User's Obsidian SEO Audit technical specification supplied in this session.

## Constraints and decisions
- No Markdown writes, automatic network scans, external page JavaScript or fixed SEO length thresholds.
- Exact trimmed HTTP(S) URL strings are deduplicated; all file paths retained. Invalid URLs are skipped.
- Code point lengths; arrays preserve duplicate tags and absent fields.
- Timeout defaults to 30 seconds. Native requestUrl cannot abort physical requests; timed-out requests retain transport slots until settled. Stop cancels the logical queue immediately.
- Final URL remains null unless the runtime explicitly supplies one; no redirect guesses from Location or canonical.
- English/Ukrainian UI, auto locale via public getLanguage(), minimum Obsidian 1.8.7.
- Pagination bounds table rendering; exported results include every indexed URL and source path.

## Tasks
- [x] 1. Scaffold Sample Plugin build, schema and parser; tests for Unicode, duplicates, malformed HTML, missing attributes and unlimited alternates.
- [x] 2. Implement incremental frontmatter index, validated serialized persistence, bounded HTTP transport and cancellable queue; test errors/timeouts/physical concurrency and index updates.
- [x] 3. Implement localized ItemView, details, settings, filtering, sorting, columns, selection, progress, file/browser actions and CSV/JSON downloads.
- [x] 4. Document installation and API constraints; run full tests, TypeScript and production build; review requirements and resulting files.

## Review focus
Requests completing after timeout/stop must not overwrite newer results. Cache loading must reject unsupported schemas without discarding them. File rename/delete/property changes must update all URL associations. Duplicate and empty tags must remain visible in details/exports. CSV must preserve nested metadata and prevent spreadsheet formula execution.

## Completion record
- Fresh independent review identified two important findings: unbounded permit acquisition and Markdown link interpretation of literal source filenames.
- Both reproduced with failing regression tests, then fixed. Physical permits remain held while logical acquisition waits have a bounded timeout. Sources resolve through Vault.getFileByPath and WorkspaceLeaf.openFile, skipping missing files.
- Full suite: 31 tests passed, 6 test files. Strict TypeScript and production build passed. Generated main.js passes Node syntax validation.
- Development dependency audit after upgrading Vitest/esbuild: zero vulnerabilities.
- No commits and no Markdown vault writes. No live Obsidian/Vault smoke test was performed in this environment.
