# Obsidian SEO Audit

Незалежний плагін Obsidian для перевірки SEO-метаданих вебсторінок із YAML frontmatter. Працює через офіційний Obsidian Plugin API. Налаштування збірки та життєвий цикл плагіна засновано на [obsidian-sample-plugin](https://github.com/obsidianmd/obsidian-sample-plugin); демонстраційних функцій Sample Plugin немає.

## Встановлення

Потрібні Obsidian **1.8.7+** і Node.js **22.12+ (гілка 22)** або **24+ (парна LTS-гілка)** для розробки.

```sh
npm ci
npm test
npm run build
```

Створіть у Vault каталог `.obsidian/plugins/seo-audit/` та скопіюйте туди **main.js**, **manifest.json**, **styles.css** із кореня цього проєкту. Перезапустіть Obsidian або перезавантажте плагіни та увімкніть **Obsidian SEO Audit** у Community plugins. Node.js не потрібен для використання вже зібраного плагіна.

## Використання

Додайте властивість до Markdown-файлу:

```yaml
---
url: https://example.com/page
---
```

Підтримується також список:

```yaml
---
url:
  - https://example.com/page
  - https://example.com/another
---
```

Натисніть іконку **SEO Audit** на бічній панелі або виконайте команду **Open SEO Audit / Відкрити SEO Audit**. Індекс містить лише абсолютні HTTP(S) URL. Початкові рядки URL обрізаються по краях; однакові рядки об'єднуються в один запис із посиланнями на всі відповідні файли. Відмінності у query string, фрагменті чи кінцевому `/` зберігаються як окремі URL.

- **Перевірити всі** запускає сканування всього індексу. **Перевірити вибрані** — сторінок, позначених прапорцями, включно з вибраними на інших сторінках таблиці. Прапорець у заголовку вибирає поточні 50 рядків.
- Пошук охоплює URL, повні шляхи файлів і зібрані метадані, включно з H1, мовними альтернативами та X-Robots-Tag.
- HTTP-фільтр підтримує групи статусів, конкретні отримані коди, помилки та неперевірені сторінки. Фільтр наявності метаданих працює для перевірених сторінок; порожні й пробільні значення вважаються відсутніми.
- Заголовки стовпців перемикають сортування. Меню **Стовпці** зберігає вибір видимих полів.
- Натискання рядка відкриває всі значення й довжини, дублікати тегів, усі H1 та повний список hreflang. Підтримано клавіші Enter/Space.
- Посилання у стовпці URL відкриває браузер, посилання на файл відкриває вихідну нотатку.
- **Зупинити** скасовує чергу й ігнорує незавершені результати. Уже збережені результати залишаються.
- **Експорт JSON / CSV** завантажує всі сторінки поточного індексу, незалежно від фільтрів і вибору. Неперевірені сторінки також включено.

Відкриття Obsidian та зміни нотаток оновлюють лише локальний індекс. Мережеве сканування запускається виключно користувачем. Плагін **не змінює Markdown і frontmatter**.

## Налаштування

| Налаштування | Типове значення |
| --- | --- |
| Назва властивості верхнього рівня у frontmatter | `url` |
| Максимум паралельних HTTP-запитів | `3` (від 1 до 20) |
| Таймаут запиту | `30` секунд (від 1 до 300) |
| Мова інтерфейсу | Автоматично за мовою Obsidian |

Доступні українська та англійська мови. Для інших мов Obsidian використовується англійська. Автовибір використовує офіційний `getLanguage()` (доступний із Obsidian 1.8.7). Зміни параметрів запитів застосовуються до наступного сканування.

## Дані та обмеження API

Запити виконуються методом GET через [`requestUrl()`](https://docs.obsidian.md/Reference/TypeScript%20API/requestUrl) з `throw: false`, щоб отримувати статус і HTML навіть для HTTP-помилок. Час HTTP-відповіді вимірюється до повного отримання відповіді; це **не TTFB**. Для мережевої помилки або таймауту повної відповіді немає, тому її час і статус дорівнюють `null`. Дата перевірки записується у UTC (ISO 8601), у таблиці показується в локальному часі.

Поточний офіційний [`RequestUrlResponse`](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts) не містить кінцевого URL після redirect. Значення `finalUrl` залишається `null`, якщо середовище явно його не повернуло; плагін не виводить його з canonical або Location. X-Robots-Tag зберігається без втрат у формі, доступній API: усі окремі значення, якщо вони доступні, або об'єднаний рядок заголовка. Плагін не може відновити окремі оригінальні заголовки з уже об'єднаного рядка.

`requestUrl()` не підтримує AbortSignal чи фізичне скасування. Таймаут і кнопка зупинки завершують логічне очікування; нативний запит може продовжуватися. Він займає слот до завершення, щоб реальна кількість HTTP-запитів не перевищувала встановлений ліміт, зокрема при повторному запуску сканування. Очікування слота також обмежене налаштованим таймаутом: якщо нативні запити зависли, наступні сторінки отримують окрему помилку таймауту очікування слота, а пакет завершується. Сам HTTP-запит має власний таймаут після отримання слота. Пізні результати після таймауту або зупинки ігноруються.

Парсер використовує інертний `DOMParser`, не виконує JavaScript сторінки й не вставляє завантажений HTML у UI. Він збирає початковий HTML, а не DOM після клієнтського рендерингу. Некоректну розмітку відновлює HTML-парсер браузера; не-HTML відповіді мають окрему помилку. За відсутності Content-Type використовується перевірка початку HTML. Присутні URL-атрибути зберігаються у початковому вигляді, без перетворення відносних URL на абсолютні.

Кожне значення має структуру `{ value, length }`. Довжина — кількість **Unicode code points**, не UTF-16 code units і не графем; комбінувальні знаки та компоненти складених emoji рахуються окремо. Пробіли та порожні атрибути зберігаються. Відсутні теги — порожні масиви; відсутні скалярні дані — `null`. Фіксованих SEO-лімітів довжин немає.

Сховище — стандартний файл плагіна `data.json` у його каталозі, окремо від нотаток:

```json
{
  "schemaVersion": 1,
  "settings": { "urlProperty": "url", "concurrency": 3, "timeoutMs": 30000, "language": "auto", "visibleColumns": [] },
  "cache": { "schemaVersion": 1, "latest": {} }
}
```

`cache.latest` містить актуальний результат за ключем URL, час перевірки, HTTP-дані, помилку й метадані. Повторне сканування замінює актуальний результат; історія поки не зберігається. Версії схем та окремий контейнер кешу дозволяють додати історію/міграції. Результати URL, видалених з нотаток, залишаються в кеші та знову доступні при поверненні URL; таблиця й експорт відображають поточний індекс. Записи серіалізовано та об'єднано в короткі пакети. Непідтримувана або пошкоджена схема зупиняє завантаження плагіна без перезапису наявних даних.

CSV має UTF-8 BOM і CRLF; масиви, помилки та вкладені метадані записуються як JSON усередині екранованих CSV-комірок. Це зберігає всі дублікати, альтернативи й довжини. Потенційні формули в текстових комірках екрануються апострофом; JSON-експорт зберігає оригінальні рядки без цього перетворення.

## Розробка

```sh
npm run dev        # esbuild watch
npm run typecheck  # TypeScript strict
npm test           # Vitest + jsdom
npm run build      # TypeScript + production bundle
```

| Модуль | Відповідальність |
| --- | --- |
| `src/main.ts` | Життєвий цикл Obsidian та з'єднання модулів |
| `src/indexer.ts` | Інкрементальний індекс URL ↔ файли |
| `src/scanner.ts` | HTTP, фізичні слоти, таймаути, черга, зупинка |
| `src/parser.ts`, `src/types.ts` | HTML-поля, Unicode-довжини та схема |
| `src/storage.ts` | Валідація, налаштування та черга збереження |
| `src/table.ts`, `src/view.ts` | Запити таблиці, ItemView та деталі |
| `src/settings.ts`, `src/i18n.ts` | Налаштування й переклади |
| `src/export.ts` | JSON/CSV та завантаження файлів |

Для нового текстового SEO-поля розширте `fieldKeys` і його правило парсингу. Таблиця, пошук, деталі, валідація кешу та експорт використовують спільну схему. Майбутні SEO-перевірки можна додати окремим модулем поверх `AuditResult`, не змінюючи початкові значення.

Тести перевіряють парсер, Unicode, дублікати, некоректний HTML, повний список альтернатив, оновлення індексу, HTTP-помилки/таймаути/ліміти/зупинку, збереження, експорт, фільтри, локалізацію та взаємодію DOM-інтерфейсу. DOM-тести використовують невелику підміну API; ручну перевірку в реальному Vault потрібно виконувати в Obsidian.
